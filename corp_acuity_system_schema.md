# Corp Acuity: System Architecture \& Data Pipeline Schema

**Purpose of this Document:**
This file serves as the master architectural map for the Corp Acuity Quantitative Screener and Broadcast Engine. **Future AI Assistants:** Read this entire document to understand file dependencies, execution order, and data routing before suggesting modifications to the Python scripts, GitHub Actions, or HTML frontends.

\---

## 1\. High-Level Pipeline Flow (Execution Order)

The entire system is orchestrated by a single GitHub Action (`.github/workflows/daily-scanner.yml`) which runs daily. The sequence is strictly linear to prevent stale data desyncs:

1. **Market Engine (`scanner.py`):** Downloads fresh market data, filters tickers based on regime/liquidity/asymmetry, and selects the top setups.
2. **Data Export:** `scanner.py` exports internal CSVs and JSON payloads.
3. **Asset Generation:** `scanner.py` triggers the internal visual scripts to draw charts and compile the PDF slide deck.
4. **State Commit:** The GitHub Action commits all newly generated files back to the main `market-screener` repository.
5. **Website Deployment:** The GitHub Action clones the front-end `corpacuity-website` repo, copies the fresh HTML/JSON/PDF data into it, and pushes it live.
6. **Social Broadcast:** The GitHub Action runs the LinkedIn and X (Twitter) Python scripts, which consume the fresh JSON/PDF/Images and broadcast them to the public.

## 2\. File Manifest \& Core Dependencies

### Core Engine

* **`scanner.py`**: The master brain.

  * *Inputs:* `yfinance` data, `sector\_cache.json`, `zacks\_rank\_tracker.json`.
  * *Outputs:*

    * `terminal\_feed.json` (Full dataset read by the website dashboard).
    * `latest\_post\_meta.json` (The elite, curated setups read by the social scripts).
    * `master\_screener\_results.csv` (Internal master record).
    * `watchlist\_\*.csv` (4 category-specific CSVs exported *strictly* for the chart engine to read).
  * *Crucial Logic:* It explicitly imports and calls `generate\_live\_charts.py` and `pdf\_engine.py` at the very bottom of the script.

### Visual \& Charting Engines

* **`generate\_live\_charts.py`**: The candlestick charting engine.

  * *Inputs:* Reads `watchlist\_\*.csv` files generated by `scanner.py`.
  * *Outputs:* Saves beautiful chart PNGs directly into the `assets/cards/` directory.
* **`pdf\_engine.py`**: The slide deck generator.

  * *Inputs:* Reads `latest\_post\_meta.json`.
  * *Outputs:* Generates `daily\_market\_intelligence.pdf` (for the website and LinkedIn) and exports individual slide images to the `x\_cards/` directory.

### Social Broadcast Scripts

*(Note: These scripts DO NOT generate charts or PDFs themselves. They assume `scanner.py` already built them.)*

* **`dispatch\_x\_intent.py`**: The Twitter thread engine.

  * *Inputs:* Reads `latest\_post\_meta.json` for text, and reads images from `assets/cards/`.
  * *Action:* Formats a 4-part thread and emails it via SMTP to the user as a click-to-tweet intent dashboard.
* **`publish\_linkedin.py`**: The LinkedIn carousel engine.

  * *Inputs:* Reads `latest\_post\_meta.json` for narrative text, and uploads `daily\_market\_intelligence.pdf`.
  * *Action:* Pushes directly to the LinkedIn API using environment tokens.

### Web Frontend (Resting in `corpacuity-website` repo)

* **`intel.html`**: The main Institutional Terminal Dashboard.

  * *Logic:* Contains vanilla JavaScript that fetches `terminal\_feed.json` on page load to populate the regime status, macro banners, and dynamic tables.
* **`index.html`**: The landing page.

  * *Logic:* Features a built-in PDF viewer (PDF.js) that displays `daily\_market\_intelligence.pdf`.

## 3\. "Gotchas" \& Strict Rules for Future Edits

1. **The Single Workflow Rule:** NEVER split the pipeline into multiple GitHub workflows (e.g., separating the screener from the broadcast). Doing so causes GitHub to check out stale files for the second workflow. Everything must run in `daily-scanner.yml`.
2. **Chart Paths:** X intent emails look for candlestick charts in `assets/cards/`. PDF slide images live in `x\_cards/`. Do not mix these directories up in the broadcast scripts.
3. **No CSVs on the Website:** The `master\_screener\_results.csv` and `watchlist\_\*.csv` files are for backend processing and local records ONLY. They are intentionally excluded from the website deployment script to protect proprietary data.
4. **Editing Social Text:** If you want to change what the LinkedIn or X posts say, you must edit the `PHRASE\_MATRIX` inside `dispatch\_x\_intent.py` and `post\_writer.py`.
5. **Editing Website Layout:** Edits to the web dashboard must be made to `intel.html` locally, and then pushed via `sync\_github.py`. The GitHub Action handles moving it to the separate live web server repo.
